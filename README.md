## 更新了什么

### 1.1.3 · 列表下载按钮可见性（2026-11-12）

问题表现：列表可以勾选作品，但看不到“下载已选”按钮。
原因是作品列表有自己的滚动条，面板主体也有滚动条；按钮被挤到面板可见区域下方。
修复通过独立 CSS 覆盖，将列表操作栏设置为底部吸附，并提供背景与分隔线，避免与滚动条目重叠混淆。
按钮沿用原来的下载事件与选择状态，未改动下载引擎。

Mac Chrome 实机检查：1.1.3 按钮完整处于面板可见区域，显示“下载已选 8 个”，非禁用状态；刷新后恢复了原来选择的 8 条作品。
这次验证覆盖布局及启用状态，没有额外启动批量下载。

### 1.1.2 · 当前视频识别

问题表现：先打开视频 A，再滑动到视频 B，下载面板仍可能抓取 A。
已确认的触发条件是地址同时包含背景视频路径 `/video/A` 和当前弹窗参数 `modal_id=B`。
原解析器优先返回 A；修复后先读取有效的 `modal_id` / `modalId`，再回退到路径编号。

例如：`https://www.douyin.com/video/1111111111111111111?modal_id=2222222222222222222`

- 原版结果：`1111111111111111111`
- 修复结果：`2222222222222222222`
- 没有有效弹窗编号时，继续使用路径编号。

此外，脚本修改本地构建名称和版本，移除原固定身份 key 及自动更新地址，跳过商店校验元数据。
不增加权限，不修改下载引擎、画质选择、暂停续传或网络接口。
修复针对上述 URL 识别优先级；若平台切换视频却不更新地址，不保证此修复适用。

## 使用

需要 Python 3.8+，无第三方依赖。请自行取得有权使用的原版未打包扩展目录，里面应有 `manifest.json`、`lib/aweme-parse.js` 和 `content/content.css`。

```sh
python3 fix.py "/path/to/original-extension" "/path/to/fixed-extension"
```

1. Chrome 打开 `chrome://extensions`，启用开发者模式。
2. 选择“加载未打包的扩展程序”，选择输出目录。
3. 停用旧版，刷新抖音页面。
4. 打开视频并滑动切换，确认下载面板标题跟随当前作品，再下载。

原目录保持不变；输出目录已存在或解析器结构不匹配时，脚本拒绝覆盖。
输出目录需要长期保留。此本地版本不会自动接收原版商店更新。
